# 优选模式

`ALL·优选` 与狮城、香港、日本、美国、中国台湾、其它地区的优选入口共用一个候选池。先识别实际出口 IP、查询风险信息，再在合格节点中比较延迟。每个优选组分别记住节点，当前节点合格且可用时保持选择，不追逐几毫秒的变化。

首次安装默认关闭后台探测。默认信誉服务为 ProxyCheck，可不注册、不填 Key，设置 `enabled: true` 后使用。普通模式和家宽落地可照常使用。尚未启用或没有合格节点时，优选入口保持拒绝连接，不自动回退到机场普通模式或本地直连。

## 配置和使用

1. 安装包含当前脚本的版本。首次接入优选时选择“使用新默认配置”，或者将监听入口、优选组及业务组引用正确迁入个人 YAML。已有优选组的旧配置会定向迁移为自动收集订阅，保留其他配置；更早、完全没有优选组的 YAML 不会自动增加整套功能。
2. 编辑设备上的 `/data/adb/box_bll/clash/private/preferred.json`，设置 `enabled: true`、`reputation_provider: "proxycheck"`，`proxycheck_key` 留空即可使用匿名查询。旧文件没有这些新增字段时可按下文的兼容规则工作。若想使用免费账户的额度或匿名查询被服务拒绝，可在 [ProxyCheck 免费注册页](https://proxycheck.io/pricing/) 用邮箱申请 Key，填入 `proxycheck_key`。密钥只保存在设备私有文件，不上传仓库、不发到聊天或日志。
3. `controller`、`controller_secret` 必须与正在使用的 mihomo 控制端口和密码一致。默认使用 `http://127.0.0.1:9090`，不允许填写远程控制器。若修改探测端口，同时修改 YAML 中对应 listener 的端口与 JSON 的 `probe_port`、`management_port`；二者不能相同。
4. 重启核心，或以 Root 执行 `/data/adb/box_bll/scripts/box.preferred start`。在总模式或业务组中选择所需优选入口。首次分批扫描需要时间，未选出合格节点前会暂时不可用。
5. 不填 ProxyCheck Key 时，信誉请求经被测节点发出，查询该节点刚测得的 IP；不通过 `优选·检测连接` 代查。填入 Key 后，或使用 IPQS 时，信誉请求经固定的 `优选·检测连接`，默认直连；若直连不可达，可手动选一个可信的具体机场节点。它独立于优选结果，不能引用总模式、家宽或优选组，以免形成循环依赖。

兼容已有设置：没有 `reputation_provider` 时，非空的旧 `api_key` 表示继续使用 IPQS；旧 `api_key` 为空则采用 ProxyCheck。显式设为 `"ipqs"` 时，仍需在 `api_key` 填入 IPQS Key。`proxycheck_key` 仅发送给 ProxyCheck，`api_key` 仅发送给 IPQS，不互换、不自动转用其它服务。已有 Key 被拒绝时也不会降级为匿名请求。

例：OpenAI 选择 `ALL·优选`，Claude 选择 `狮城地区·优选`，Linux.do 选择 `香港地区·优选`。它们共享检测结果，但 ALL 的选择变化不会直接改写地区组。多个业务引用同一个优选组时，共用该组的出口。

地区以被测出口 IP 的 `country_code` 为依据，不能仅凭节点名称断言位置。默认 ALL 和其它地区优选也保持上次选择的国家/地区；没有同地区合格替代节点时保持不可用。允许它们自动跨地区切换需要显式设置 `allow_country_change: true`；指定地区优选始终不跨地区。

订阅和节点从正在运行的 mihomo 自动发现。订阅改名、新增或删除，只要配置本身成功加载，下一轮本地检查就会采用当前数据，不需要在 `preferred.json` 再维护一份名称列表。旧文件中的 `providers` 字段兼容保留但不再读取；Key、预算和历史记录不受影响。

探测组、七个内部出口组及检测连接组使用 `include-all-providers: true` 自动收集订阅。候选来自核心实际提供的 HTTP、文件和内联 provider，并与探测组的可选节点核对；核心生成的 `Compatible` 副本不重复计算。家宽节点按 `家宽·出口` 的实际成员排除，因此家宽 provider 改名也不会被误当作普通机场节点。直连、拒绝、DNS、rematch 和其他策略组不进入候选池。不同真实来源的节点同名时会排除，以免混用两条线路的记录。

## 检测和频率

探测只发送小型 HTTPS 请求，不做大文件带宽测试，也不自动化登录、注册或触发验证码。两个 listener 只监听 `127.0.0.1`：默认 `7894` 用于逐节点取得出口 IP，并承载该节点的匿名信誉请求；`7895` 用于带 Key 的固定管理连接和连通性复核。首次检查仍需先取得出口 IP，再带上这个 IP 查询信誉，不能假定匿名 API 会自动返回请求者的报告。探测器只切换自己的内部探测组，不用总模式轮换节点，也不删除全部现有连接。

默认使用 [ProxyCheck v3 API](https://proxycheck.io/api/)，请求指定 IP 并设置 `tag=0`，关闭该查询在账户正向检测日志中的保存。它的原始风险分会把机房、VPN、代理身份计入基础分；代理即使没有已记录攻击，也可能为 100。因此不套用 IPQS 的 74 分阈值：默认 `proxycheck_max_risk: 100`，同时要求 `compromised`、`scraper`、`tor` 都明确为 false，`attack_history` 中没有正数计数。VPN、机房、代理标记本身不直接排除，仍保留原始风险分用于候选排序。更低的 `proxycheck_max_risk` 可以加强筛选，也可能排除正常代理线路。

空的 `attack_history` 对象只表示该服务没有返回已记录攻击，不证明 IP 没有历史问题。缺失或为 null 的历史、缺失或类型错误的检测字段、未知风险分、返回了其它 IP 的报告，都按未知处理。原始风险分不伪装成另一家服务的分数，也不被改写为零。有效的已知额度提示可以接受；其它警告、拒绝、限流和格式错误会触发退避。

兼容的 [IPQS API](https://www.ipqualityscore.com/documentation/proxy-detection-api/overview) 继续使用 `strictness=0`、`allow_public_access_points=true`，要求 `fraud_score <= max_risk`（默认 74），且 `recent_abuse`、`bot_status` 都明确为 false。两种服务分别保存报告，切换后没有该服务有效记录的节点需重新检测，不能借用另一家的评分。各自在合格候选内按风险分段排序，再优先较少发生出口变化的线路，最后比较延迟；延迟优先复用核心近期健康检查的中位数，缺少结果时才对合格节点补测。

没有有效延迟结果的线路暂不选入新候选，即使其 IP 风险较低；当前已经选定且仍可用的节点不会仅因一条延迟记录缺失而更换。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `review_interval` | 86400 秒 | 日常复评当前出口及每个正在使用的优选组的少量备用，不每日全量查询 |
| `exit_interval` | 3600 秒 | 确认当前节点出口是否改变 |
| `selection_max_age` | 3600 秒 | 自动选入节点前允许使用的报告年龄；过期时补查 |
| `daily_budget` | 100 | 每个 UTC 自然日所有节点、所有服务合计最多发出的信誉查询次数，失败请求也计数；不是每个 IP 各 100 次 |
| `request_gap` | 5 秒 | 优选器相邻探测操作的起始时间至少间隔这么久 |
| `batch_size` | 5 | 每轮处理的节点上限；当前使用的节点优先 |
| `backups` | 2 | 每个正在使用的优选组日常维护的备用数量 |
| `max_risk` | 74 | 仅用于 IPQS 的风险上限，可配置范围 0–89 |
| `proxycheck_max_risk` | 100 | 仅用于 ProxyCheck 的原始风险上限，范围 0–100；还必须通过上述攻击记录及检测项检查 |
| `poll_interval` | 60 秒 | 读取本机控制器、判断组选择和到期任务的间隔；不代表每分钟访问外部接口 |
| `check_ipv6` | true | 同时尝试取得 IPv6 出口，并独立查询其信誉 |

首次启用时，当前订阅中尚未检查的节点按批次建立记录；之后新增节点补测。多个节点共用同一个出口时，共用该 IP 的报告，线路延迟分别保存。周期任务在未使用优选时不扫描；手动 `scan` 可以在尚未选择优选时预热候选池，并仍遵守间隔、缓存和预算。

上述间隔约束优选器发起的操作；原有 provider 健康检查以及核心统一延迟测试内部的请求仍由 mihomo 调度，不是设备所有网络请求的统一限速。

发现出口变动时，旧 IP 的报告不会用于新 IP。普通发现任务保留每日额度最后 10% 给当前出口与切换前验证。接口异常按 15 分钟、1 小时、6 小时退避，服务端整数秒 `Retry-After` 更长时使用该值。匿名请求的拒绝或限流按观测到的出口单独退避，共享该出口的其它节点也遵守；不换其它出口代查被拒绝的 IP。服务故障、格式错误或带 Key 的请求失败暂停该服务的查询。重启核心不重置额度、报告或选择记忆。

ProxyCheck 官方目前允许未注册来源每天 100 次、免费账户每天 1,000 次；前者按服务实际看到的请求来源计算，可能与机场其他用户共享，而且服务明确可能拒绝经代理发出的匿名请求。匿名功能是尽力查询，不保证每个出口都可用。供应商可能针对不同目的地或 IPv4/IPv6 使用不同出口，因此本地按节点 IPv4 记录的退避只是一项保护，不能当成服务端额度证明；全局预算始终保留。程序不会通过改变查询来源来突破额度。IPv6 报告单独查询，但访问 API 的连接不保证也使用 IPv6。

报告是带时间戳的风险快照，不是实时信誉保证。当前仍可用且未出现新坏记录的已知出口可以继续沿用历史结果；自动选入过期候选需要复查。因此信誉服务短期不可用不会把原有好节点集体判坏，但未知的新出口不会自动晋升。全部候选都缺乏合格结果时，优选入口不可用。

故障切换要求核心的健康检查失败，并通过另一个探测目标复核，累计三次、各次至少间隔 300 秒。管理连接也不可达时暂不据此累积节点故障，避免把本地断网当成所有节点失效。控制器不可用时不改动已有选择。切换节点不能迁移已有 TCP 会话，也可能中断长连接。

## 维护命令与数据

以 Root 运行：

```sh
/data/adb/box_bll/scripts/box.preferred status
/data/adb/box_bll/scripts/box.preferred scan
/data/adb/box_bll/scripts/box.preferred stop
/data/adb/box_bll/scripts/box.preferred start
```

`scan` 是分批重新检查请求，不绕过缓存和每日预算。`stop` 停止调度器；若希望彻底停用，先把业务组切回其它模式，再设 `enabled: false`。核心启动/停止会联动调度器；非正常终止留下的锁在确认原进程已退出后回收。不要直接手动操作隐藏的 `优选·…出口` 组。

禁用，或选择 IPQS 却缺少其 Key 时，调度器清理内部选择后退出，不持续拉取节点数据。ProxyCheck 没有 Key 仍可运行。重新配置后需执行 `start` 或重启核心。订阅元数据获取失败时保留现有选择，不把缺失的快照当成节点已删除。

`status` 显示最近一次运行结果、自动发现的来源名称、候选数量及最近查询状态；它本身不会启动扫描。`Disabled` 表示未启用，`IPQS API key missing` 表示选了 IPQS 却没有 Key，`No candidate nodes` 表示没有可探测节点，`No qualified nodes yet` 表示尚无通过检测的候选。控制器或发现接口失败会单独说明，并保留原选择。修改设置后可先保持普通线路，执行 `scan` 预热，再查看状态并切回优选。

每轮发现读取一份完整 provider 注册表，避免逐个名称请求期间发生改名导致数据混合。解析时跳过核心生成副本的重复节点图；该注册表响应上限为 32 MiB，其他控制器响应保持 4 MiB。超限、缺字段或解析失败按发现失败处理，不当作空订阅。

模块 disable、设备 `manual` 和网络控制的 `wifi_bypassed` 标记存在时暂停探测，恢复后按到期任务继续；卸载前停止调度器。HTTPS 使用系统 CA 校验，不关闭证书验证。

设置、账本和日志位于 `clash/private/`，目录权限 `0700`、文件 `0600`。`preferred/report.tsv` 保存每条线路的出口、风险、检测时间、出口变化次数及信誉服务来源；其中节点名采用 URI 编码。旧 `preferred/ips` 保存 IPQS 报告，`preferred/ips.proxycheck` 保存 ProxyCheck 报告。`preferred/events.log` 记录选择和故障原因，日志有大小上限，`status` 显示当前服务、是否匿名、总预算和最近查询状态。备份此目录可能包含 API Key，应保存在自己的设备或可信备份中。

安装包仅携带 `preferred.example.json` 默认模板。首次安装初始化私有设置；重复升级保留已存在的设置、API Key、报告与选择记忆，不覆盖整个个人 JSON。旧节点账本可读，后续扫描更新其服务来源字段。脚本和平铺的 JSON/策略解析模块随版本更新，私有目录不参与普通递归权限重设，也被源码快照和 ZIP 排除。

覆盖升级选择“保留我的配置”时，独立迁移脚本只为本模块九个优选内部组补充自动收集属性，保留订阅名称、URL、其他分组和个人规则。块式分组、流式映射和流式分组列表均支持定向处理；变更先用设备核心校验，通过后才替换。首次修改前另存 `config.yaml.preferred.bak`，已有该备份时不覆盖；重复迁移没有变化则不写文件。不明确或校验失败时保留所选 YAML 并中止安装，不能用整份默认配置掩盖问题。

## 能力边界与验证

- 查询不会提升 IP 本身的信誉，数据库评分也不等于网站内部风控。机房、VPN、住宅等属性不能单独证明好坏；同一出口还会受其它使用者影响。
- 固定节点不保证供应商固定出口。检测是采样，节点可能在两次检查之间换 IP，也可能对不同目的地采用不同出口。希望更严格固定出口时，应使用供应商实际保证固定的家宽落地。
- 探测是 TCP/HTTPS。已取得的 IPv4/IPv6 分别检查，两者地区不一致或任一已知地址不合格时，不选入该线路。IPv6 回显不可用不等于所有 IPv6 流量都没有出口；UDP/QUIC、WebRTC 和特定业务的真实出站仍需设备验证，本功能没有新增全局 UDP 禁用。
- 业务规则、模块停用、系统旁路与 Rule/Global/Direct 模式继续影响实际流量，优选组不是设备级防泄漏开关。未使用的内部选择会在下轮本机轮询时回到拒绝，重新激活时恢复并复核记忆；启动和手动切换存在轮询窗口。
- 当前 SurfingTile 为预编译 APK，在线配置覆写是否保留新增 listeners 和组必须实测；`webroot/index.html` 只是面板跳转页。首次使用建议核对实际核心配置及连接链。
- 本地验证使用真实 mihomo、BusyBox、模拟 SOCKS5 和本机信誉 API，检查请求是否经对应节点、共享查询、地区分流、过期报告、配额、按出口退避、出口变化、解析错误、切换服务及旧设置兼容，不访问真实账号。命令见 [tests/README.md](../tests/README.md)。ProxyCheck 对真实机场节点是否允许匿名访问仍需少量实测；上线前还需验证 Android Shell、系统 CA 信任、网络切换、睡眠、启动/停止、IPv4/IPv6 和实际供应商出口。
