# 优选模式

`ALL·优选` 与狮城、香港、日本、美国、中国台湾、其它地区的优选入口共用一个候选池。先识别实际出口 IP、查询风险信息，再在合格节点中比较延迟。每个优选组分别记住节点，当前节点合格且可用时保持选择，不追逐几毫秒的变化。

首次安装默认关闭后台探测。普通模式和家宽落地可照常使用；启用优选需要自己的 IPQS API Key。没有配置或没有合格节点时，优选入口保持拒绝连接，不自动回退到机场普通模式或本地直连。

## 配置和使用

1. 覆盖安装时选择“使用新默认配置”，或者将新的监听入口、优选组及业务组引用正确迁入个人 YAML。保留完整旧 YAML 不会自动增加新功能。
2. 编辑设备上的 `/data/adb/box_bll/clash/private/preferred.json`。把 `api_key` 填为自己的 IPQS Key，设置 `enabled: true`。密钥只保存在这个设备私有文件，不上传仓库、不发到聊天或日志。API 的字段和可用配额由自己的账号套餐决定。
3. `controller`、`controller_secret` 必须与正在使用的 mihomo 控制端口和密码一致。默认使用 `http://127.0.0.1:9090`，不允许填写远程控制器。若修改探测端口，同时修改 YAML 中对应 listener 的端口与 JSON 的 `probe_port`、`management_port`；二者不能相同。
4. 重启核心，或以 Root 执行 `/data/adb/box_bll/scripts/box.preferred start`。在总模式或业务组中选择所需优选入口。首次分批扫描需要时间，未选出合格节点前会暂时不可用。
5. `优选·检测连接` 默认直连，负责访问 IPQS；若当前网络无法直连，可在这个组手动选择一个可信的具体机场节点。它独立于优选结果，不能引用总模式、家宽或优选组，以免形成循环依赖。

例：OpenAI 选择 `ALL·优选`，Claude 选择 `狮城地区·优选`，Linux.do 选择 `香港地区·优选`。它们共享检测结果，但 ALL 的选择变化不会直接改写地区组。多个业务引用同一个优选组时，共用该组的出口。

地区以被测出口 IP 的 `country_code` 为依据，不能仅凭节点名称断言位置。默认 ALL 和其它地区优选也保持上次选择的国家/地区；没有同地区合格替代节点时保持不可用。允许它们自动跨地区切换需要显式设置 `allow_country_change: true`；指定地区优选始终不跨地区。

`providers` 默认列出 `1.主要地址`、`2.备用地址`、`3.额外地址`，只读取这些订阅的元数据，避免拉取核心生成的大量重复 provider 内容。自定义订阅名称时同步此列表，并保证探测组的 `use` 引用相应订阅；两者取交集。节点名称应在订阅间保持唯一，重复名称会排除，以免把两条不同线路的记录混用。

## 检测和频率

探测只发送小型 HTTPS 请求，不做大文件带宽测试，也不自动化登录、注册或触发验证码。两个 listener 只监听 `127.0.0.1`：默认 `7894` 用于逐节点取得出口 IP，`7895` 用于固定管理连接查询信誉。探测器只切换自己的内部探测组，不用总模式轮换节点，也不删除全部现有连接。

信誉查询使用 [IPQS API](https://www.ipqualityscore.com/documentation/proxy-detection-api/overview)，固定 `strictness=0`、`allow_public_access_points=true`。默认要求 `fraud_score <= 74`，且 `recent_abuse` 和 `bot_status` 都明确为 false。缺字段、格式错误、接口报错均为未知，不能当作零风险。风险分段相同时，优先较少发生出口变化的线路，再比较延迟；延迟优先复用核心近期健康检查的中位数，缺少结果时才对合格节点补测。

没有有效延迟结果的线路暂不选入新候选，即使其 IP 风险较低；当前已经选定且仍可用的节点不会仅因一条延迟记录缺失而更换。

| 设置 | 默认值 | 作用 |
| --- | --- | --- |
| `review_interval` | 86400 秒 | 日常复评当前出口及每个正在使用的优选组的少量备用，不每日全量查询 |
| `exit_interval` | 3600 秒 | 确认当前节点出口是否改变 |
| `selection_max_age` | 3600 秒 | 自动选入节点前允许使用的报告年龄；过期时补查 |
| `daily_budget` | 100 | 每个 UTC 自然日最多发出的信誉查询次数，失败请求也计数 |
| `request_gap` | 5 秒 | 优选器相邻探测操作的起始时间至少间隔这么久 |
| `batch_size` | 5 | 每轮处理的节点上限；当前使用的节点优先 |
| `backups` | 2 | 每个正在使用的优选组日常维护的备用数量 |
| `max_risk` | 74 | 可接受的 IPQS 风险上限，可配置范围 0–89 |
| `poll_interval` | 60 秒 | 读取本机控制器、判断组选择和到期任务的间隔；不代表每分钟访问外部接口 |
| `check_ipv6` | true | 同时尝试取得 IPv6 出口，并独立查询其信誉 |

首次启用时，三个订阅中尚未检查的节点按批次建立记录；之后新增节点补测。多个节点共用同一个出口时，共用该 IP 的报告，线路延迟分别保存。周期任务在未使用优选时不扫描；手动 `scan` 可以在尚未选择优选时预热候选池，并仍遵守间隔、缓存和预算。

上述间隔约束优选器发起的操作；原有 provider 健康检查以及核心统一延迟测试内部的请求仍由 mihomo 调度，不是设备所有网络请求的统一限速。

发现出口变动时，旧 IP 的报告不会用于新 IP。普通发现任务保留每日额度最后 10% 给当前出口与切换前验证。接口异常按 15 分钟、1 小时、6 小时退避，服务端整数秒 `Retry-After` 更长时使用该值。重启核心不重置额度、报告或选择记忆。

报告是带时间戳的风险快照，不是实时信誉保证。当前仍可用且未出现新坏记录的已知出口可以继续沿用历史结果；自动选入过期候选需要复查。因此信誉服务短期不可用不会把原有好节点集体判坏，但未知的新出口不会自动晋升。全部候选都缺乏合格结果时，优选入口不可用。

故障切换要求核心的健康检查失败，并通过另一个探测目标复核，累计三次、各次至少间隔 300 秒。管理连接也不可达时暂不据此累积节点故障，避免把本地断网当成所有节点失效。控制器不可用时不改动已有选择。切换节点不能迁移已有 TCP 会话，也可能中断长连接。

## 维护命令与数据

以 Root 运行：

```sh
/data/adb/box_bll/scripts/box.preferred status
/data/adb/box_bll/scripts/box.preferred scan
/data/adb/box_bll/scripts/box.preferred stop
/data/adb/box_bll/scripts/box.preferred start
```

`scan` 是分批重新检查请求，不绕过缓存和每日预算。`stop` 停止调度器；若希望彻底停用，先把业务组切回其它模式，再设 `enabled: false`。核心启动/停止会联动调度器；非正常终止留下的锁在确认原进程已退出后回收。不要直接手动操作隐藏的 `优选·…出口` 组。

禁用或缺少 Key 时，调度器清理内部选择后退出，不持续拉取节点数据。重新配置后需执行 `start` 或重启核心。订阅元数据获取失败时保留现有选择，不把缺失的快照当成节点已删除。

模块 disable、设备 `manual` 和网络控制的 `wifi_bypassed` 标记存在时暂停探测，恢复后按到期任务继续；卸载前停止调度器。HTTPS 使用系统 CA 校验，不关闭证书验证。

设置、账本和日志位于 `clash/private/`，目录权限 `0700`、文件 `0600`。`preferred/report.tsv` 保存每条线路的出口、风险、检测时间和出口变化次数；其中节点名采用 URI 编码。`preferred/events.log` 记录选择和故障原因，日志有大小上限。备份此目录会包含 API Key，应保存在自己的设备或可信备份中。

安装包仅携带 `preferred.example.json` 默认模板。首次安装初始化私有设置；重复升级保留已存在的设置、API Key、报告与选择记忆。脚本和平铺的 JSON/策略解析模块随版本更新，私有目录不参与普通递归权限重设，也被源码快照和 ZIP 排除。

## 能力边界与验证

- 查询不会提升 IP 本身的信誉，数据库评分也不等于网站内部风控。机房、VPN、住宅等属性不能单独证明好坏；同一出口还会受其它使用者影响。
- 固定节点不保证供应商固定出口。检测是采样，节点可能在两次检查之间换 IP，也可能对不同目的地采用不同出口。希望更严格固定出口时，应使用供应商实际保证固定的家宽落地。
- 探测是 TCP/HTTPS。已取得的 IPv4/IPv6 分别检查，两者地区不一致或任一已知地址不合格时，不选入该线路。IPv6 回显不可用不等于所有 IPv6 流量都没有出口；UDP/QUIC、WebRTC 和特定业务的真实出站仍需设备验证，本功能没有新增全局 UDP 禁用。
- 业务规则、模块停用、系统旁路与 Rule/Global/Direct 模式继续影响实际流量，优选组不是设备级防泄漏开关。未使用的内部选择会在下轮本机轮询时回到拒绝，重新激活时恢复并复核记忆；启动和手动切换存在轮询窗口。
- 当前 SurfingTile 为预编译 APK，在线配置覆写是否保留新增 listeners 和组必须实测；`webroot/index.html` 只是面板跳转页。首次使用建议核对实际核心配置及连接链。
- 本地验证使用真实 mihomo、BusyBox、模拟 SOCKS5 和本机信誉 API，检查实际脚本、重复查询、地区分流、过期报告、配额、限流、出口变化、解析错误及安装保留，不访问真实账号。命令见 [tests/README.md](../tests/README.md)。上线前仍需验证 Android Shell、系统 CA 信任、网络切换、睡眠、启动/停止、IPv4/IPv6 和实际供应商出口。
